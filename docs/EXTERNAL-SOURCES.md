# 外部数据源：怎么自己加

> 这份文档给**部署这个项目的人和他的 AI** 看。
>
> 我们不提供"全国所有学校的资讯"，因为那不可能做对也维护不动。
> 我们提供的是**模板 + 范例 + 这套方法**，你照着自己加。

---

## 先说清为什么不内置一百个学校

三个理由，都不是"懒得做"：

1. **学校官网有几百种后台**。有的是静态 HTML，有的是 Vue SPA，有的套着统一门户。
   一套通用爬虫覆盖不了，硬写只会到处是特例。
2. **域名不统一**。同一个城市的两所学校可能是 `ustl.edu.cn` 和 `lnkj.edu.cn`。
   猜域名会把人带到**仿冒站**——这比不给链接更危险。
3. **我们不知道你的学校长什么样**。硬编码进去的东西，改版一次就全废，
   而且废了没人知道（没人会去逐个验证一百个学校）。

**所以**：`src/info/sources.mjs` 里只有 5 个**全国性**的范例源，
剩下的交给你的 AI 按下面的步骤加。

---

## 一个源能做三件事

| 类型 | 给什么 | 什么时候用 |
|---|---|---|
| `official-entry` | 只给 URL | **最稳**。改版了链接也还在，不需要维护 |
| `api` | 能直接取数据 | 目标页是 XHR 拉数据时。要验三样（见下） |
| `search` | 搜索引擎链接 | 拿不准域名时。**不猜**，让搜索引擎带你去 |

**优先级：official-entry > search > api**。

反直觉但对：`api` 排最后，因为它最脆——签名会变、字段会改名、反爬会升级。
能用入口就用入口。

---

## 三步拆解流程

### 第一步：判断它是静态还是动态

用浏览器打开目标页，**F12 → Network → 刷新**。

- **View Source 里能看到标题**（右键 → 查看网页源代码）→ **静态**，最简单，`fetch` 一次就能拿。
- **HTML 是空壳，数据在 XHR 里** → 记下那条 XHR 的：
  - URL 与查询参数
  - **有没有 `enc` / `sign` / `token` 之类**（有的话多半是签名，很难啃）
  - 请求头里有没有必须的 Referer
- **整页 JS 渲染 + 接口带签名** → **先别做**。标成「需要浏览器」，
  走 CDP 路线（本仓库的 `src/api/pan.mjs` 就是这个套路：开一次 headless Chrome，
  让页面自己请求，抓下真实 URL 复用）。

### 第二步：判断能不能做

| 条件 | 结论 | 怎么做 |
|---|---|---|
| 公开可访问，不需要登录 | ✅ 能做 | 正常抓 |
| 需要校内账号登录 | ⚠️ 降级 | 只做「打开页面让人自己看」，不抓内容 |
| 有验证码 / 强反爬 | ❌ 不做 | 改成给搜索入口 |
| 内容是 PDF 附件 | ⚠️ 部分做 | 给下载链接，**不解析内容**（解析 PDF 是另一个问题） |
| 数据要 POST 且带签名 | ⚠️ 谨慎 | 见下面「签名的三种情况」 |

#### 签名的三种情况（按难度）

1. **不校验**：参数里带个 `sign` 但服务端不验 → 直接抓（实测过这种）
2. **可反推**：`md5(字段拼接)` → 试几种常用 secret 就能撞出来
   （本仓库的视频任务点 `enc` 就是这样，公式已写进 `docs/API.md`）
3. **反推不出**：掺了时间戳/随机数/服务端密钥 → **只能走 CDP 现取**
   （本仓库的云盘 `enc` 属于这种：试了 43 种 md5 组合都没命中，
   且验证了它绑定参数，换 parentId 就失效）

**不要在这上面死磕**。第 3 种情况如果花了半小时还没头绪，直接换 CDP。

### 第三步：写成源对象并验真

照 `SOURCE_TEMPLATE` 填。六项必填：

```js
{
  id: 'ustl-notice',              // 小写短横线，全局唯一
  name: '某某大学 通知公告',
  kind: 'api',                    // official-entry | api | search
  url: 'https://www.example.edu.cn/api/notice?page=1',
  scope: '某某大学',               // 全国 / 某省 / 某校
  howFound: '从学校官网首页底部的「通知公告」点进去，F12 看到 XHR 是 /api/notice?page=1',
  verified: '2026-11-28',         // 最后一次验证日期
  note: '每页 20 条；需要 Referer 头，否则 403',
}
```

**`howFound` 是最重要的一项**。它是给后来人的线索：
没有它，三个月后没人知道这个 URL 是怎么来的、还能不能信。

`cxa info sources` 会跑 `validateSource` —— 缺 `howFound` 直接报错，
这是故意设的硬要求。

## 验真：HTTP 200 不等于成功

这一步**不能省**。已经踩过的坑：

| 看起来成功 | 实际 |
|---|---|
| HTTP 200 | 返回了 15 字节的「无权限下载」文案 |
| HTTP 200 | body 里 `errcode != 0`（推送接口） |
| 页面有 `<title>` | 是个「暂无数据」的空壳 |
| 有 20 条列表 | 全是「加载中…」的占位 |

**验真四件套**：

1. **条目数 > 0**
2. **标题不是**「暂无数据」「加载中」「请稍后」
3. **抽一条打开**，确认是对的目标页（不是 404、不是登录页）
4. **第二天再跑一次**，确认不是缓存/一次性

过了才把日期填进 `verified`。

## 三个真实范例（要点）

### 范例 1：官方入口（最省事）

```js
{ id: 'cet-signup', kind: 'official-entry', url: 'https://cet-bm.neea.edu.cn/' }
```

**不要在这上面加"考试日期"字段**。四六级的考试时间每年每省都不同，
写死过一次就得年年改，改漏了就误人。

真要给时间，给「通常 6 月与 12 月」这种**标注为规律**的说法，
并在输出里明确写「不是官方公布的日期」。

### 范例 2：搜索页（不猜域名）

```js
{ id: 'school-site-search', kind: 'search',
  url: 'https://www.bing.com/search?q=' + encodeURIComponent('某某大学 官网') }
```

**为什么不直接给学校官网 URL？** 因为猜错了会把人带到仿冒站。
搜索结果页让人一眼能认出哪个是真官网，比猜一个链接安全得多。

### 范例 3：XHR 接口（最脆，但有价值）

```js
{ id: 'ustl-notice', kind: 'api',
  url: 'https://www.example.edu.cn/api/notice?page=1&size=20',
  note: '需要 Referer 头；返回 {data: {list: [...]}}，list 项有 title/url/date' }
```

**注意**：`note` 里写清**返回结构**。这样下一个人改版后能快速对比哪里变了。
本仓库在通知接口上就吃过这个亏——`coursename` 藏在 `cparams.funConfig.content`
三层深，第一版按 `cparams.courseName` 取，结果课程显示成裸数字 id。

## 硬边界（写进提示词，也写进代码）

| 不做 | 原因 |
|---|---|
| **猜域名** | 学校域名不统一，猜错会到仿冒站 |
| **写死考试日期** | 每年每省都不同，写死必错 |
| **绕过登录 / 验证码** | 需要登录的源只做「打开页面」 |
| **编内容** | 抓不到就说抓不到，不要用模板话术填 |
| **自动提交表单** | 只读。会改变对方系统状态的操作一律不做 |

## 把这件事交给你的 AI

```bash
cxa info sources
```

最后会打印一段**完整的提示词**，直接复制给你的 AI。它会：
1. 被告知先看页面判断静态/动态
2. 拿到「能不能做」的判断表
3. 被要求照 `SOURCE_TEMPLATE` 填
4. 被要求跑验真四件套
5. 被明确禁止猜域名、写死日期、绕登录

**这段提示词是活的**——改 `src/info/sources.mjs` 的 `buildAddSourcePrompt`
就能调整，不需要改文档。
