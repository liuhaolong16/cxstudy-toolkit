# 接入手机端 AI（豆包 / WorkBuddy / 千问）

> 本文所有"能做到"的结论都附了来源链接。查证时间：2026-11-28。
> 产品能力会变，用之前请按链接再核一遍。

## 一句话结论

**手机端 AI 可以远程操控你的电脑**，所以它**能调用本项目的 `cxa` 命令和 MCP 工具**。
"到点提醒"不是靠聊天 AI 主动推送，而是靠**在手机上给电脑建一个定时任务**。

```
手机 AI  ──远程指令──▶  电脑端 AI  ──调用──▶  cxa / mcp  ──▶  超星
   ▲                                                   
   └────────── 进度与结果回传手机 ──────────────────────────┘
```

## 一、WorkBuddy（三家里文档最全，优先选这个）

官方文档：[多端协同（连接电脑）](https://www.workbuddy.cn/docs/workbuddyapp/features/Multidevice)

### 原文里明确写着的

| 能力 | 原文 |
|---|---|
| 定位 | 「手机成为桌面端 Agent 的『**远程控制台**』」 |
| 远程续聊 | 「移动端进入对话继续发送指令，**指令将在桌面端 WorkBuddy 执行**」 |
| 远程配置 | 「技能、专家、**连接器**、权限、模型在手机上也能配置，**均以电脑端为准**」 |
| 任务通知 | 「任务完成、中断、等待回答、等待审批时**主动通知到手机**」 |
| 定时任务 | 「**遥控电脑创建自动化任务**：点击『定时任务』，描述要做的事并选择执行频率（每天 / 每周 / 每月等），保存后**电脑会按设定时间自动执行**」 |
| 产物回传 | 「WorkBuddy 在电脑上产出的文件会**自动回传到 App**」 |

### 接入步骤

**① 电脑端准备好（一次性）**

```bash
cd <项目目录>
install.cmd          # 或 npm install -g github:liuhaolong16/chaoxing-assistant
cxa auth login       # 登录超星，cookie 落盘
cxa auth status      # 确认会话可用
```

**② 把 MCP 挂到 WorkBuddy 的连接器**

WorkBuddy 的连接器面板在对话输入框的 `+` 里。配 stdio MCP：

```json
{
  "mcpServers": {
    "chaoxing": {
      "command": "node",
      "args": ["<项目绝对路径>/mcp/server.mjs"]
    }
  }
}
```

配好后能用 10 个工具：`cx_status` / `cx_courses` / `cx_exams` / `cx_materials` /
`cx_schedule` / `cx_chapters` / `cx_notices` / `cx_play` / `cx_http` / `cx_gates`。

**③ 电脑端开「允许移动端连接此设备」**

侧边栏底部悬停「连接移动端」图标 → 打开开关。
**同时建议开「允许锁屏运行」**，否则电脑锁屏后手机连不上。

**④ 手机端连上**

装 WorkBuddy App，**登录同一账号** → 侧边栏顶部设备入口 → 选择这台电脑。

**⑤ 建定时任务（这就是"到点提醒"）**

手机 App → 输入框旁的 `+` → 「定时任务」→ 描述要做的事、选频率。
例：

> 每天早上 7:30 执行 `cxa brief`，把结果发给我

保存后**电脑按时间自动跑**，跑完**结果回传手机**，任务完成会**主动通知**。

### WorkBuddy 的限制（原文都写了）

- **电脑必须在线**，离线时手机显示「离线」，不能交互
- 电脑关机 / 断网 → 定时任务和远程指令都不会执行
- 「允许锁屏运行」不开的话，锁屏后连不上

## 二、豆包

来源：[豆包"工作任务"支持手机远程操控电脑 · 北京市科委转载北京商报](https://kw.beijing.gov.cn/xwdt/kcyx/xwdtyqqy/202608/t20260818_4827272.html)（2026-08-18）

### 原文里明确写着的

> 「同一账号授权后，用户在手机端下达任务指令，可以由**已连接的电脑端读取本地文件、操作软件完成执行**，进度和结果实时回传手机」

> 「使用该功能需在豆包官网下载最新的『**豆包电脑版**』，并将手机端豆包 App 更新至最新版，在『**工作任务**』模式中点击『**云电脑**』，并在对话运行环境中选择『**添加新的本地电脑**』完成授权」

> 「支持关联**多台电脑**，可跨设备调取文件」

### 接入步骤

1. 电脑装**豆包电脑版**（官网下载，必须最新版）
2. 手机豆包 App 更新到最新版，**登录同一账号**
3. 手机进入「**工作任务**」模式 → 点「**云电脑**」
4. 对话运行环境 → 「**添加新的本地电脑**」→ 授权
5. 之后手机下达任务，电脑执行

### 豆包的限制

- **官方文档没有提到 MCP**。所以大概率不能像 WorkBuddy 那样挂 MCP server，
  而是让它**直接在电脑上跑命令**（`cxa brief` 这类）
- 具体能不能跑 shell 命令、能不能设定时任务，**官方公告里没写**——
  按上面的入口实测一次，我这里不替它下结论

**已确认**：Qwen Chat **桌面客户端支持一键唤起调用 MCP**。

所以千问目前能确认的用法是：**在电脑上的 Qwen Chat 里挂 MCP**（同 WorkBuddy 的 ②）。
手机端远程这块，等有官方文档再说，我不猜。

## 四、三个方案的可靠度排序

| 方案 | 会不会响 | 前提 | 可靠度 |
|---|---|---|---|
| **① `.ics` + 手机系统日历** | **会**（系统级推送，**离线也响**） | 无 | ★★★★★ |
| **② 手机 AI → 电脑 → 定时任务 → 通知回手机** | 会 | **电脑要开机且联网** | ★★★☆☆ |
| ③ 手动 `cxa brief` 粘给 AI | 不会响 | 电脑要开 | ★★☆☆☆ |

**① 用来"报时"（不能替代），② 用来"顺带帮你干活"（查资料、刷课、生成简报）。
两个都用，不要指望一个顶两个。**

② 的失效面很清楚：**电脑睡了就不响**。所以凡是不允许漏的提醒（考试、交作业），
**一律走 ①**。

## 五、给 AI 的调用顺序

不管哪家，让 AI 按这个顺序来，出问题最好定位：

```
1. cxa auth status          # 先确认会话
2. cxa brief                # 今天/未来几天上什么课、有什么考试
3. cxa exams                # 未结束的考试
4. cxa schedule --today     # 只要今天
5. cxa schedule --ics <目录>  # 要日历就导
6. cxa materials --cid .. --clz .. --find <关键词>   # 找课件
```

**MCP 版对应**：`cx_status` → `cx_schedule` → `cx_exams` → `cx_materials`。

## 六、安全边界

- **不要把 `~/.cxstudy-toolkit/cookies.json` 提交或分享**——那是你的登录凭证
- 手机端授权的是「**你这台电脑上的 WorkBuddy/豆包**」，不是直接给你电脑的 shell
- 远程指令**以你本人身份和你已授权的范围**执行，不会扩大权限
- 用完不需要时，在电脑端或手机端**断开设备连接**
