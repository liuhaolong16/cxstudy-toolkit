# 任务点完成判定：实测记录（含后续修正）

> 2026-11-26。本文档是实验记录，**不是**产品承诺。
> **重要**：第 7 节的「后续修正」推翻了第 1 节的绝对化表述，请先读第 7 节。

---

## 1. 最初的结论（后被修正，保留原文以示过程）

**无头（及有头屏幕外）播放 + 页面自发心跳上报，可以让视频真实播放，但无法让学习通把任务点标记为「已完成」。**

因此当时判断：`cxstudy play` 是一个**真实播放器**，不是一个「刷课器」。

## 2. 实验设计

样本：`WPS-2024`（courseId 246180456 / classId 106042289），知识点 1.1（knowledgeId 906664402），视频时长 131.5s。

对照组与变量：

| 变量 | 取值 |
|---|---|
| 浏览器模式 | `--headless=new` / 有头但窗口置于屏幕外 (`--window-position=-2500,-2500`) |
| 播放终点 | `currentTime >= duration-1` / 真正触发 `ended` 事件 |
| 静音 | 全部静音（`muted` + `volume=0` + `--mute-audio`） |
| 自动播放策略 | `--autoplay-policy=no-user-gesture-required` |

## 3. 观测结果

四种组合，结论一致：

```
BEFORE  {"clear":1,"finish":0,"cls":["ans-job-icon ans-job-video ans-job-icon-clear "]}
play: ok
  t=131/132
  >>> video ENDED event fired
AFTER   {"clear":1,"finish":0,"cls":["ans-job-icon ans-job-video ans-job-icon-clear "]}
```

上报确实发出且被接受（含真正 ended 那次）：

```
pt=0    {"isPassed":true,"videoTimeLimit":false,"hasJobLimit":false}
pt=17   {"isPassed":true,"videoTimeLimit":false,"hasJobLimit":false}
pt=77   {"isPassed":true,"videoTimeLimit":false,"hasJobLimit":false}
pt=131  {"isPassed":true,"videoTimeLimit":false,"hasJobLimit":false}
```

课程章节页的「已完成任务点」计数在完整播放前后**同样不变**（26/84 → 26/84）。

## 4. 被排除的三个假设（针对上面的样本）

| 假设 | 实验 | 结果 |
|---|---|---|
| A. 无头浏览器被检测，上报被静默丢弃 | 换有头、窗口移到屏幕外重跑 | 同样不变 → 排除 |
| B. 需要真正触发 `ended` 而非接近片尾 | 改为等待 `v.ended === true` 再检查 | 仍然 clear → 排除 |
| C. 播放中丢了焦点/被节流导致时长不足 | 加 `--disable-background-timer-throttling` 等四项防节流 | `currentTime` 稳定推进 → 排除 |

## 5. 对 `isPassed` 的判定

`{"isPassed":true}` **不是「任务点完成」**，而是「本次心跳通过校验」。

依据：该字段为 `true` 的同时，页面上的任务点状态类始终停留在 `ans-job-icon-clear`，且课程级计数不增加。若 `isPassed` 表示完成，两者应同步变化。

**这一条至今仍然成立。**

## 6. 当时认为客户端无法推进的原因

完成判定发生在服务端，客户端只提交观看位置。当时列了三个不可控条件：

- 教师端为该知识点配置的完成条件（页面显示「观看时长需 ≥ 总时长的 90%」，已达 100%，仍不通过）
- 服务端是否存在累计口径要求（分多次、分散观看）
- 是否需要额外的「学习完成」提交动作

## 7. 后续修正（2026-11-26 晚，同一台机器）

### 新观察

换到另一门课（`习近平新时代中国特色社会主义思想概论`，courseId `265932816`）做对照，出现了与原结论矛盾的现象：

| 谁播的 | 视频 | 任务点 | 课程计数 |
|---|---|---|---|
| `cxstudy play`（headless） | 欢迎你入课 291s | 橙色 1，**没变** | 10/40 → 10/40 |
| 我自己起的 `--headed` 浏览器 | 学习榜样 140s | 橙色 1，**没变** | — |
| **用户真实登录的 Chrome** | 欢迎你入课 291s | **变成绿色 ✓** | 10/40 → **11/40** |

### 找到的客观差异

用户浏览器里有四个**课程级 cookie**，而 `~/.cxstudy-toolkit/cookies.json`（从客户端导出的 19 条账号级 cookie）里**没有**：

```
265932816enc    265932816ut    265932816cpi    265932816t
```

这些是平台在**真实访问该课程时**下发的，绑定了课程 + 时间戳 + 会话。

同时确认：用户浏览器的 `localStorage` 是**空的**（`lsCount: 0`），所以差异不在 localStorage，而在 cookie 层。

### 修正后的表述

**原结论「播放不能让平台记账」过于绝对，应改为：**

> **能否记账取决于浏览器的可信度。**
> 用 `~/.cxstudy-toolkit/cookies.json` 手动注入 cookie 的浏览器（无论 headless 还是有头）**不会被记账**；
> 用户自己真实登录、带课程级 cookie 的浏览器**可以**。

### 仍然不确定的部分（必须写清楚）

1. **只观察到一次计数变化**（10/40 → 11/40），样本量 1，不足以宣称"稳定可复现"。
2. **可能是延迟记账**。用户浏览器播完后，我当场读到的是橙色 1，几分钟后再读就变成绿色勾。无法排除"headless 播的那次在服务端延迟生效"这一解释。
3. **2 倍速是否被判异常未确证**。观察到的成功案例是 2x 播放，但只此一例。
4. **未控制变量**：用户可能在 Chrome 里自己点过那些视频。

### 因此，当前的工程结论

1. **不要靠 CLI 播放来指望记账**——它仍然只是一个真实播放器。
2. **要记账，用 `extension/` 里的浏览器扩展**，装在你自己登录过的浏览器里（见 [EXTENSION.md](EXTENSION.md)）。
3. `progress` 门保持诚实：给前后读数，由读数决定红绿，**不预设结论**。
4. 任何"保证刷完一学期"的说法都不成立——即使浏览器对了，视频时长还得一秒一秒走。

## 8. 追加（2026-11-27 01:44）：抓错 `<video>`，之前所有"扩展播放"结论作废

### 现场

用户截图里同一个页面出现两个差一个数量级的时间：

```
播放器：12:17 / 1:43:52   = 737 秒
浮窗：  81 / 6232          = 81 秒
```

### 原因

扩展 0.2.0 的 `findAnyVideo()` 取的是页面上**第一个** `<video>`。学习通播放页有多个 video 元素（预加载壳、隐藏元素），第一个是个 81 秒的空壳。脚本一直在对它下播放/倍速/静音命令，**主播放器完全没动**。

### 后果

**所有「扩展播了会被记账」的观察全部不成立**，因为扩展从未真正驱动过主播放器。之前看到的进度增长，只能来自用户自己观看，或 CLI 播放的延迟记账。

### 修法（0.3.x）

- `findAnyVideo` 按 `duration` 降序取最大（主视频几十分钟，壳子通常 NaN 或极短）
- 新增 `muteAll()` 静音页面上全部 video/audio
- 浮窗加诊断后缀：`81/6232 · 2x · 静音 · [3个:6232,81,0]`，直接显示选中的是哪个

### 新的验收判据

**浮窗秒数必须等于播放器显示秒数。** 不一致就是还在管错元素，此时任何"进度上涨"都不能归因于本工具。

### 教训

这条和前面几节的错误是同一个根：**用"看起来对"的信号代替"实际对象正确"的验证**。

- isPassed=true 不代表完成
- 浮窗在跑不代表在管主播放器
- 进度上涨不代表是本工具造成的

每次都该先问：**我操作的到底是哪个对象？**

## 9. 复现方法


```bash
# 原始实验（WPS 课）
node .cxstudy-re/phase0-headed.cjs 9351 headed     # 有头屏幕外
node .cxstudy-re/phase0-headed.cjs 9351 headless   # 无头

# 新对照（思政课，需要你自己登录的浏览器）
# 1) 装扩展：scripts/install-extension.ps1
# 2) 打开课程视频页，看右下角浮窗是否出现
# 3) 播完一节后，回章节页看该任务点是否从橙色 1 变成绿色勾
```

判定标准：章节页的「已完成任务点」分母是否变化，以及目标任务点的 class 是 `ans-job-icon-clear`（未完成）还是绿色勾（已完成）。
