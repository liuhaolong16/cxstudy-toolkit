# 超星学习通小助手

**契约在 `AGENT-CONTRACT.md`**（能力边界、决策树、五个坑、演进规则）。
本文件是操作手册：告诉你每条命令什么时候用、怎么用、坏了怎么查。

---

## 零、什么时候**不该**用（先看这个，比看能干什么更重要）

| 用户说的 | 该用谁 | 为什么不是我们 |
|---|---|---|
| 「这个 PDF 讲什么」/「把它转成 Word」 | `pdf` / `pdfkit-py` | 我们没有 PDF 解析；`cxa materials` 只负责**下载**，不负责读 |
| 「帮我整理这个 Excel / 改这个 Word」 | `xlsx` / `docx` | 通用文档处理 |
| 「帮我点一下这个网页的按钮」 | `agent-browser` | 通用浏览器自动化；我们只用浏览器做学习通内部的事 |
| 「帮我写作业 / 写论文」 | **都不该用** | 硬边界：我们只整理复习材料，不代写 |
| 「考试中帮我答题」 | **都不该用** | 硬边界：作弊 |
| 「帮我查个四六级政策」 | 先问清楚 | 如果只是要**常识**，直接答就行，别为这个装工具；`cxa info` 是给「要官方入口」的场景 |

**判据**：**任务里有没有「超星/学习通这个平台」这一环**。有 → 我们；没有 → 找专门的技能。

## 一、先做这一步（永远）

```bash
cxa auth status
```

**任何异常都先跑它。** 90% 的"没数据"是登录态失效，不是功能坏了。
未登录 → `cxa auth login`（开有头浏览器，你手动扫码/输账号）。

拿到课程坐标：

```bash
cxa courses          # 输出 courseId / clazzId / cpi —— 后面几乎所有命令都要用
```

**不要瞎猜课程名**。有重名课时用 `--cid --clz` 指定。

## 二、20 条命令，按场景分

### 查数据（只读，直接跑）

| 想做什么 | 命令 |
|---|---|
| 有哪些课 | `cxa courses` |
| 这门课有哪些章、还差多少 | `cxa chapters --cid <id> --clz <id>` |
| 有什么考试 | `cxa exams`（默认只要未结束的，`--all` 看全部） |
| 有什么通知 / 没交的作业 | `cxa notices` / `cxa notices --work` |
| 找课件 / 下载资料 | `cxa materials --course <名> --find <词>` |
| 云盘根目录 | `cxa pan` |

### 课表与时间

| 想做什么 | 命令 |
|---|---|
| 本周课表 | `cxa schedule` |
| 指定周 | `cxa schedule --week 13` |
| 今天 / 明天 + 空闲时段 | `cxa schedule --today` / `--tomorrow` |
| **导到手机日历（带提前提醒）** | `cxa schedule --ics <目录>` |
| 未来 N 天：课 + 考试 + 空闲 | `cxa plan --days 14` |
| 一段粘给 AI 的简报 | `cxa brief --days 7` |

`.ics` 是**唯一离线也会响**的提醒方式。每个事件带提前 20 分钟 `VALARM`，
`--alarm N` 改提前量、`--no-alarm` 关掉。

### 备考（本项目最想做的事）

```bash
cxa exam --course <课程名> [--out <目录>] [--json] [--no-video]
```

生成一份 Markdown，包含：
- **资料分级**：教案/大纲/习题（权重 6/5/4）优先于普通课件（2）
- **章节证据**：作业章节（权重 5/3）+ 课件 + **视频总时长**（参考列）
- 考试倒计时、老师通知、给 AI 的提示词

`--no-video` 跳过视频时长采集（省一次浏览器启动 + N 次请求，约 10 秒）。

### 会改平台状态的（**必须先问用户**）

| 命令 | 做什么 | 为什么要先问 |
|---|---|---|
| `cxa play --cid --clz` | 后台静默连播视频 | 会改观看进度 |
| `cxa notify set` / `notify test` / `notify brief` | 推送到微信/飞书/钉钉/Server酱/PushPlus | 会向外部服务发请求 |
| `cxa mcp` | 启动 MCP server | 起一个常驻进程 |

`manifest.json` 里这些标 `kind=write`。**用户没说"帮我播"，就不要自己跑 `play`。**

### 自检与外部资讯

| 命令 | 做什么 |
|---|---|
| `cxa check` | 5 道判据门（env/auth/target/reachable/progress），红项带 `evidence`。**查运行时环境** |
| `cxa audit` | **交付面审计**：文档数字/清单/过时结论 vs 实现 + **Skill 健康**。**查仓库自洽性** |
| `cxa heal` | **自愈**：按配方改自己代码（默认预演）。`--apply --yes` 才真改，验证不过自动回滚 |
| `cxa feedback ok\|bad [理由]` | 标记这次用得对不对。**Skill 健康的唯一半自动数据源**——不调就永远「样本不足」 |
| `cxa info` | 四六级 / 计算机等级 / 考研 / 考公的官方入口与一般规律 |
| `cxa info sources` | 列外部源模板 + 打印"加自己的源"的提示词 |
| `cxa --version` | 版本 |

**`check` / `audit` / `heal` 的分工**：`check` 问「我现在能不能用」；`audit` 问「我对外说的对不对」；`heal` 是「发现不对之后，能自动改的改掉」。

**`feedback` 是这套评估里最弱也最关键的一环**：触发准确率、一次通过率、返工率
**在宿主层根本测不了**（详见 `docs/SKILL-EVAL.md`），只有「用对了没有」能靠人/AI 标。
所以用着觉得对或不对，顺手 `cxa feedback ok` / `cxa feedback bad 理由`。

## 三、典型用户意图 → 命令序列

```
"我有哪几门课"
  → cxa auth status → cxa courses

"这门课还差多少"
  → cxa courses（找 cid/clz）→ cxa chapters --cid --clz

"帮我看完这门课"
  → 先问用户确认 → cxa play --cid --clz
  （播放的记账条件见 AGENT-CONTRACT.md 第五节 5 条，四条齐了才会变绿）

"我下周要考什么 / 怎么安排"
  → cxa exams → cxa plan --days 14

"给我一份备考档案"
  → cxa courses → cxa exam --course <名> --out <目录>
  → 读完档案后**主动说诚实边界**（见第五节）

"课表导到手机上"
  → cxa schedule --ics <目录>
  → 告诉用户去手机日历导入 .ics

"找找有没有讲义 / 课件"
  → cxa materials --course <名> --find 讲义
  （搜的是完整路径，不是只匹配文件名）

"有作业要交吗"
  → cxa notices --work

"四六级怎么准备 / 考研考什么"
  → cxa info（给官方入口和一般规律）
  → 注意：不猜具体院校政策，让用户查官网或问学长
```

## 四、失败了怎么查

| 现象 | 先跑 | 再判断 |
|---|---|---|
| 任何异常 | `cxa auth status` | 未登录 → `cxa auth login` |
| 列表为空 | `cxa check` | 看哪道门红，红项有 `evidence` 照着修 |
| 播放了但进度没涨 | `cxa check` | 看四条件链缺哪条 |
| 推送没收到 | `cxa notify test` | 看**业务码**，不是 HTTP 状态 |
| MCP 连不上 | `node mcp/server.mjs` | 手发一个 `initialize` 看有无回包 |
| 怀疑项目坏了 | `node scripts/selftest.mjs` | 9 项（含交付层一致性门），空输出算失败 |
| 档案里视频时长全是 `—` | 正常 | 那门课没做成视频，不代表那章不重要 |

**搜不到课件**：确认用的是 `--find`（递归搜索）。只列根目录会漏掉子目录里的。

## 五、三条必须主动告诉用户的诚实边界

### 1. 备考档案给的是「分级证据」，不是「复习重点」

区分度依赖三样：**作业章节**（最准）+ **教案/大纲/习题** + **视频时长**。

**三者都没有的课**（只有课件 PDF）→ 档案会退化成"课件清单"，**排不出优先级**。
这时必须明说，并给替代路径：精读教案 / 把习题全做一遍 / 联网查本校考纲。

**不要把"课件份数多"当成"这章重要"**：资料区常有 `教案PDF/` `课件PDF/`
`课件PDF版/` 三个并列目录，拍平后同一内容算三份，**份数本身是重复计数的**。

### 2. 播放要记账，需要四个条件同时成立

1. 从 `studentcourse` 章节列表点击进入（带对 `enc`）
2. `enc` 是客户端 MD5 签名（不是服务端发的）
3. 真实 Chrome profile + cookies
4. 关掉后台节流

`cxa play` 已实现这四条。**少了任何一条，视频会播但任务点不变绿。**
如果用户说"播了但没涨"，先查 `cxa check`，别急着说功能坏了。

### 3. 云盘的 `enc` 不可逆推

服务端严格校验、绑定参数，43 种 md5 组合全试过都不对。
**只能用 CDP 从真实页面现取**（`cxa pan` 约 8 秒）。这不是慢，是唯一可行路径。

## 六、绝对不做（六条硬边界）

1. **不伪造任务点完成状态、不伪造学习时长**（不构造 `multimedia/log` 上报）
2. **不做考试中的实时答题** —— 那是作弊；考前生成复习材料才是本工具
3. **不绕过验证码、设备指纹、行为风控**
4. **不做多账号批量** —— 只服务使用者自己的账号
5. **不分发盗版教材、不维护题库服务器**
6. **不编造"复习重点"** —— 没有考纲时给证据 + 让用户的 AI 结合证据推断

## 七、给其他 AI 客户端

本项目的入口有四种，按你的环境选：

- **支持 MCP**（Claude Code / Cursor / WorkBuddy / 千问桌面端）→ `node mcp/server.mjs`（10 个工具）
- **有 shell** → `cxa <子命令> --json`（20 个命令，`--json` 出机器可读）
- **只能读写文件** → `.captcha-tmp/`、`.cxstudy-questions/` 里的 JSON
- **只能读文档** → `llms.txt`（一份自包含的完整说明）

机器可读的能力清单在 `manifest.json`。**改命令时必须同步它**，否则自检会红。
